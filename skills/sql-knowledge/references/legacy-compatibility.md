# Совместимость существующего проекта

Не включать для нового проекта. При явной миграции старые Python writers с несколькими mutate/BEGIN/COMMIT могут использовать sql_knowledge.legacy.bind(root). writable connect получает эксклюзивную аренду через общую очередь; SQLite закрывается до освобождения аренды. COMMIT сам по себе аренду не снимает: обязательно close/finally. Авария процесса освобождает блокировку ОС и откатывает незавершённую SQLite транзакцию. Не держать соединение между сообщениями чата. Требуется SQLite >=3.51.3; старый embedded Python использовать только для чтения, запись выполнять общим установленным Python.

Manifest явно включает [compatibility] legacy_writes=true. Это не добавляет CAS к старому blind update: существующие предметные CAS и квитанции сохраняются. Новые writers используют типизированный MCP/CLI с CAS. После изменения manifest перезапустить coordinator и MCP.

MAVIS хранит свою файловую политику scripts/project-knowledge/storage.py и Disk Budget рядом с проектом. Общий MCP может подключить только этот локальный backend с закреплёнными SHA256 storage_sha256 и storage_budget_sha256. Совместимость storage_legacy_cas=true предназначена для существующего монитора без expected_revisions; явно переданные версии проверяются, CAS ядра и расширений остаётся обязательным. Политика сохраняет защиту файлов и потребителей. Изменение pinned файлов требует проверки, новых SHA и перезапуска, иначе записи storage отвергаются.

Не отключать защитные triggers и не обходить очередь прямым SQL. SQL-дампов нет.
